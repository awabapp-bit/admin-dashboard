# منصة أواب الإلكترونية — لوحة تحكم المسؤول

موقع مستقل بالكامل عن موقع المستخدم. يشتركان فقط في نفس مشروع Firebase.

| الملف | الوظيفة |
|---|---|
| `index.html` | دخول المسؤول (نقطة الدخول) — admin / 123 |
| `home.html` | كل الكورسات والمسابقات + إحصائيات |
| `add-competition.html` | إضافة كورس أو مسابقة جديد(ة) |
| `competition.html?id=...` | إدارة محاضرات عنصر محتوى معيّن |
| `lesson.html` | محاضرة: فيديوهات متعددة + اختبارات متعددة (كبطاقات ملخص فقط: العنوان، عدد الأسئلة، إجمالي النقاط) + مرفقات (روابط PDF/صور) |
| `exam.html` | صفحة مستقلة لإدارة أسئلة اختبار واحد بالتفصيل (تُفتح من زر داخل `lesson.html`) |
| `users.html` | كل الحسابات (بما فيها حسابات المسؤولين) — بحث/عرض/إعادة تعيين/حظر |
| `user-detail.html` | تفاصيل حساب + إرسال رابط استرجاع كلمة مرور |
| `participants.html` | مشتركو (المشتركين فعليًا) عنصر محتوى معيّن ونقاطهم |
| `support.html` | لوحة محادثات الدعم الفني (مشروع Firebase مستقل تمامًا)، آخر عنصر في شريط التنقل — admin / 123456 |

## الملفات المطلوبة بجانب الصفحات (كل حاجة في نفس المستوى)
```
awab-admin-site/
├── logo.png
├── style.css
├── firebase-config.js
├── icons.js
├── admin-shell.js
└── *.html
```

## ⚠️ قبل الاستخدام
1. Firebase Console ← Authentication ← Settings ← Authorized domains ← أضف نطاق نشر هذا الموقع.
2. Firebase Console ← Realtime Database ← Rules ← الصق محتوى `firebase-rules.json` المرفق.

لا حاجة لتفعيل Firebase Storage: المرفقات أصبحت روابط خارجية يلصقها المسؤول يدويًا، مش رفع فعلي، فملف `storage-rules.txt` المرفق أصبح غير مطلوب.

## دخول المسؤول

من `index.html`:
- **اسم المستخدم:** `admin`
- **كلمة المرور:** `123`

خلف الكواليس، هذه البيانات بتسجّل دخولك تلقائيًا لحساب Firebase حقيقي: `admin@awab.su.com` بكلمة مرور `500500`. يُنشأ تلقائيًا أول مرة تسجّل دخول. الجلسة محفوظة تلقائيًا بعد أول دخول.

**فايدة إن الحساب الحقيقي معروف**: نفس الحساب تقدر تدخل بيه مباشرة في **موقع المستخدم** (مش هنا) عشان تتصفح كأي مستخدم عادي وترد على تعليقات الناس على الفيديوهات.

## كورسات ومسابقات معًا
عند إضافة محتوى جديد (`add-competition.html`)، تختار نوعه: **كورس** أو **مسابقة**. الفرق شكلي بس (تسمية الزرار والأيقونة عند المستخدم)، البنية التقنية واحدة (محاضرات فيها فيديوهات/اختبارات/مرفقات).

## الاشتراك الحقيقي
المستخدم بيشترك فعليًا (مش مجرد تصفح) من زر "اشتراك/انضمام" في صفحة تفاصيل المحتوى عنده، بعد تأكيد صريح منه. صفحة `participants.html` هنا بتعرض المشتركين الفعليين بناءً على ده (عقدة `enrollments/{compId}`)، حتى لو لسه ما بدأش أي محاضرة أو ما جمعش نقاط.

## إشعارات تلقائية للمستخدمين
- عند إضافة محاضرة جديدة لكورس أو مسابقة (من `lesson.html`): إشعار تلقائي **للمشتركين الفعليين في هذا المحتوى فقط** (مش كل المستخدمين).
- عند رد المسؤول على تعليق (من موقع المستخدم): إشعار لصاحب التعليق تلقائيًا.
- **مفيش** إشعار عام لكل المستخدمين عند إضافة كورس/مسابقة جديد بالكامل.

## الاختبارات وصفحة الأسئلة المستقلة
في `lesson.html`، قسم "الاختبارات" بيعرض كل اختبار كبطاقة ملخص فقط (العنوان، عدد الأسئلة، إجمالي النقاط) مع زرّي "تعديل/إضافة الأسئلة" و"حذف الاختبار". إدارة الأسئلة نفسها (نص السؤال، الاختيارات الأربعة، الإجابة الصحيحة، النقاط) صارت في صفحة مستقلة `exam.html`. حالة نموذج المحاضرة (العنوان، المعاد، الفيديوهات، المرفقات، كل الاختبارات) بتتحفظ مؤقتًا في `sessionStorage` (مفتاح فريد لكل كورس/محاضرة) وقت الانتقال لصفحة الأسئلة، وترجع تلقائيًا عند العودة لـ`lesson.html`. المسودة بتتمسح تلقائيًا بعد نجاح حفظ المحاضرة، أو عند الضغط على "رجوع للمحتوى".

## الدعم الفني
`support.html` صفحة محادثات دعم فني كاملة (نصوص، صور، رسائل صوتية، ملفات)، وهي آخر عنصر في شريط تنقل لوحة التحكم. تعمل على مشروع Firebase مستقل بالكامل عن مشروع الكورسات/المسابقات (نفس فلسفة الاستقلالية في هذا المشروع)، وبيانات دخولها الخاصة بها: **admin / 123456** (منفصلة عن admin / 123 الخاصة بباقي لوحة التحكم).

## المرفقات (روابط PDF وصور)
في `lesson.html`، قسم "المرفقات" بقى بيسمح بإضافة رابط خارجي جاهز (اسم + رابط + نوع PDF/صورة) لكل محاضرة، بدل رفع ملف فعلي. المسؤول لازم يرفع الملف بنفسه على أي خدمة استضافة (Google Drive، Dropbox، إلخ) ثم يلصق رابطه هنا. يظهر تلقائيًا في قائمة محتوى المحاضرة عند المستخدم. **لا يتطلب Firebase Storage** إطلاقًا.

## صفحة الحسابات
`users.html` بطاقات (مش جدول)، بتعرض **كل** الحسابات (بما فيها حسابات المسؤولين، بشارة "مسؤول" مميزة)، مع بحث وفرز (الأحدث / الأعلى نقاطًا / أبجديًا / المحظورين أولاً). أزرار تصفير النقاط والحظر مخفية تلقائيًا لحسابات المسؤولين (حماية من الحظر بالخطأ).

## ملاحظة مهمة عن إرسال رابط إعادة تعيين كلمة المرور
زر "إرسال رابط إعادة تعيين كلمة المرور" في `user-detail.html` **يرسل إيميل حقيقي فعليًا** عبر Firebase، ويوجّه المستخدم لموقع `awab-reset-site` المستقل بدل صفحة Firebase العامة.

## مهم: روابط المواقع التانية
تمت إزالة زر "عرض الموقع" نهائيًا من شريط تنقل لوحة التحكم (`admin-shell.js`). المتبقي: زر "العودة لموقع المنصة" في `index.html`، وزر إرسال رابط إعادة التعيين، وكلاهما بيشاور على مواقع مستقلة. الروابط الحالية:
```
موقع المستخدم: https://awabapp-bit.github.io/awab-user-site/
موقع إعادة تعيين كلمة المرور: https://awabapp-bit.github.io/awab-reset-site/
```
لو الروابط الفعلية بعد النشر مختلفة، حدّثهم في:
- `admin-shell.js` → `const RESET_SITE_URL`
- `index.html` → رابط "العودة لموقع المنصة" أسفل الفورم

## ⚠️ ملاحظة عن ملف storage-rules.txt
لم تعد لوحة التحكم تستخدم Firebase Storage؛ الملف مُبقًى فقط كمرجع سابق ولا حاجة للصقه في Firebase Console.

## 🎨 التصميم الجديد
تم تحديث `style.css` بالكامل لهوية بصرية عصرية واحترافية (نظام ألوان أزرق/محايد، خط Cairo موحّد في كل الصفحات بدل الخط التقليدي القديم، ظلال وتدرّجات أهدأ). التغيير في متغيرات الجذر (`:root`) بأعلى الملف فقط، فبينعكس تلقائيًا على كل صفحات لوحة التحكم دون أي تعديل إضافي.

## ⚙️ إعدادات المحتوى (تعديل كورس/مسابقة بعد إنشائه)
في `competition.html`، زر **"إعدادات المحتوى"** أعلى الصفحة يفتح فورمًا لتعديل: الاسم، الوصف، رابط صورة الغلاف، ونوع المحتوى (كورس/مسابقة) — في أي وقت بعد الإنشاء، مش بس أول مرة. صورة الغلاف بقت تظهر كمصغّرة جنب كل عنصر في `home.html` لو مُضافة.

## 🔓 فتح الاختبار لإعادة المحاولة (لأي مشترك، بلا أي شرط)
في `participants.html`، زر **"الاختبارات"** جنب كل مشترك يفتح نافذة تعرض كل اختبارات هذا المحتوى وحالتها لهذا المستخدم بالذات (لم يبدأ / جارٍ / تم التسليم)، مع زر **"فتح لإعادة المحاولة"** متاح دايمًا لأي مستخدم على أي اختبار، بغض النظر عن حالته الحالية (لسه مبتداش، مقفول، عليه مخالفات أو لأ، إلخ). هذا الزر بيمسح محاولة الاختبار الحالية (`examAttempts`) وأي مخالفات مسجلة على نفس الاختبار تحديدًا لنفس المستخدم (من غير ما يمس مخالفاته في اختبارات تانية)، ويسمح له بمحاولة جديدة من موقع المستخدم.

**حماية أعلى نتيجة (على مستوى قاعدة البيانات نفسها):** تمت إضافة قاعدة تحقّق (`.validate`) في `firebase-rules.json` تحت `userProgress/$uid/$compId/$lessonId/earnedPoints` تمنع نزول نقاط أي محاضرة عن قيمتها الحالية. يعني عمليًا: لو المستخدم أعاد الاختبار وجاب نقاطًا أعلى من المحاولة الأولى، بتتحدّث النقاط تلقائيًا للأعلى؛ ولو جاب أقل، قاعدة البيانات نفسها بترفض تخفيض النقاط وتفضل النتيجة الأولى (الأعلى) زي ما هي — بغض النظر عن أي كود في موقع المستخدم. **لازم تنسخ محتوى `firebase-rules.json` المحدَّث وتلصقه تاني في Firebase Console → Realtime Database → Rules → Publish عشان الحماية دي تشتغل فعليًا.**

## 🆕 تحديثات لوحة التحكم (الدفعة الأولى من مقترحات التحسين)

**1. الوضع الليلي (Dark Mode)**
دعم كامل عبر `data-theme="dark"` على `<html>`، بمتغيرات ألوان بديلة في `style.css`. زر التبديل موجود أسفل القائمة الجانبية (شمس/قمر)، والاختيار محفوظ في `localStorage` (`adminTheme`)، مع سكربت صغير في `<head>` كل صفحة يمنع "الوميض" عند التحميل الأول (Flash of Unstyled Theme). يتبع تفضيل نظام التشغيل تلقائيًا لو المستخدم لسه ما اختارش.

**2. إشعارات Toast**
كل استخدامات `alert()` في لوحة التحكم استُبدلت بدالة `showToast(message, type)` المعرّفة في `admin-shell.js` (النوع: `success` / `error` / `warning`، اختياري). تظهر أسفل يسار الشاشة وتختفي تلقائيًا بعد ~4 ثوانٍ، مع زر إغلاق يدوي.

**3. بروفايل المسؤول + شارة إشعارات في القائمة الجانبية**
أعلى القائمة الجانبية بيظهر تلقائيًا اسم/بريد المسؤول الحالي وحرف الأفاتار (من `renderAdminNav`)، وجنب رابط "المخالفات" شارة حمراء بعدد المخالفات المسجّلة إجمالًا.

**4. لوحة القيادة (Dashboard) في `home.html`**
بطاقات إحصائية موسّعة (8 بطاقات: إجمالي المستخدمين، النشطون، الدروس، المسابقات، الاختبارات، مشاركات اليوم، المخالفات، آخر تسجيل)، رسم بياني بالأعمدة (بدون مكتبات خارجية) لعدد المستخدمين الجدد آخر 30 يوم، قائمة "أكثر المحاضرات تفاعلاً" (حسب `userProgress`)، وقسم "آخر الأنشطة" يجمع (تسجيلات جديدة + تسليم اختبارات + مخالفات) في تايم لاين واحد.

**5. Skeleton Loading**
كلاسات `.skel` / `.skel-stat-card` / `.skel-row` جاهزة للاستخدام في أي صفحة بدل `loader` الدائري، مستخدمة الآن في `home.html`.

### حاجات لسه محتاجة شغل (من نفس مستند المقترحات) لو حبيت نكمل عليها لاحقًا:
- تعميم Dark Mode / Toast بصريًا على تفاصيل أعمق في كل صفحة (الأزرار، الجداول التفصيلية).
- صفحة "الإعدادات" (اسم المنصة، الشعار، وضع الصيانة، إلخ) — مش موجودة لسه كصفحة مستقلة.
- تصدير بيانات الجداول (Excel/CSV/PDF)، وعمليات جماعية (تحديد أكثر من مستخدم).
- اختصارات لوحة المفاتيح، وحفظ آخر صفحة تمت زيارتها تلقائيًا.
- ربط حالة "is-loading" الجديدة للأزرار بباقي عمليات الحفظ/الحذف في كل صفحة (اتربطت لحد دلوقتي في `index.html` بس، كمثال).

## 🎨 دفعة تحسين التصميم الثانية (Premium SaaS Dashboard)

تحديث شامل على `style.css` و`admin-shell.js` و`icons.js` لرفع مستوى التصميم ليكون أقرب لمنصات زي Vercel/Linear/Supabase، مع الحفاظ الكامل على منطق الصفحات وربط Firebase زي ما هو (كل التعديلات في ملفات النظام المشتركة، فبتنعكس تلقائيًا على كل صفحات لوحة التحكم).

**القائمة الجانبية** — أعيد بناؤها بالكامل: عرض أكبر، شعار في إطار مميز، بروفايل مسؤول بحلقة حول الصورة الرمزية وأيقونة "مسؤول موثّق"، وتقسيم الروابط لمجموعات بعناوين واضحة (الرئيسية / إدارة المحتوى / المستخدمون / النظام) مع مؤشر نشِط بشريط ذهبي متدرّج. نفس التقسيم شغال في وضع الجوال (القائمة المنسدلة) وفي حالة الطي (أيقونات فقط).

**لوحة الألوان** — استُبدلت بمجموعة ألوان أهدأ وأقل تشبعًا (أزرق نيلي مريح للعين + ذهبي مستخدم كلمسة تمييز فقط)، مع تحديث متوازٍ لمتغيرات الوضع الليلي لنفس درجة الراحة البصرية.

**البطاقات الإحصائية** — أرقام أكبر، أيقونة داخل خلفية دائرية بلون الهوية، ورفعة خفيفة (Hover Lift) مع ظل أنعم بدل التغيير المفاجئ.

**الجداول** — رأس الجدول بقى مثبّت أثناء التمرير فعليًا (Sticky) داخل منطقة تمرير خاصة بالجدول، صفوف أطول، وHover أوضح.

**الحركة (Micro-interactions)** — ظهور تدريجي خفيف للبطاقات والصفوف عند تحميل الصفحة، ونوافذ منبثقة (Modals) بحركة دخول ناعمة (تكبير + تلاشي) بدل الظهور المفاجئ، كل ده بيحترم إعداد "تقليل الحركة" في نظام تشغيل المستخدم (`prefers-reduced-motion`).

**حالة تحميل داخل الأزرار** — كلاس جديد `is-loading` جاهز على مستوى النظام (دوّارة تحميل بدل تغيير نص الزرار)، مُفعّل حاليًا في زرار الدخول بـ`index.html` كمثال، وقابل لتطبيقه على أي زرار حفظ/حذف تاني بنفس الطريقة.

**حالة عدم وجود بيانات (Empty State)** — تصميم أكثر دفئًا: شارة دائرية بلون ذهبي فاتح حول الأيقونة بدل الأيقونة مجردة.
